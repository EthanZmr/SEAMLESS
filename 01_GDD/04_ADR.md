# 《无缝》架构决策记录（ADR）

> 只记录会影响后续 3 个月开发的决策；新决策追加，不覆盖。

---

## ADR-001：引擎用 Godot 4.7.2（2D）

- **状态**：已采纳
- **背景**：单人开发、3 个月、PC、2D 横版动作。
- **决策**：Godot 4.7.2，GDScript，2D 渲染，`CharacterBody2D`。
- **替代方案**：Unity 2D（生态大但启动慢、2D 工作流重）；GameMaker（2D 快但扩展/3D/后期弱）；自研（时间不够）。
- **后果**：启动快、导出 Windows 简单、社区资源够；需要自己搭绳索/接缝工具链。

## ADR-002：原型期输入用 autoload 注册，M2 前迁回 InputMap

- **状态**：已被 ADR-011 取代（2026-10-22）
- **背景**：手写 `project.godot` 的 `InputEvent` 序列化容易出错；W1 要快速跑起来。
- **决策**：`InputSetup.gd` 在启动时用 `InputMap.add_action` 注册动作；键位集中在一个字典里。
- **后果**：原型快；编辑器 Input Map 面板看不到动作；M2 前写迁移脚本或手工迁回。

## ADR-003：绳索/纤维用“作者指定段数”的假绳

- **状态**：已采纳
- **背景**：全物理绳索在 2D 动作里容易抖动、穿模、不可预测；单人调试成本高。
- **决策**：纤维由 6–10 个固定段组成，段间用弹簧/距离约束；摆荡用手调参数；不做自由绳结。
- **后果**：手感可控、性能好；视觉上够用；复杂绳结谜题不做。

## ADR-004：美术走“霓虹剪影 + shader”

- **状态**：已被取代（2026-10-21 美术方向锁定为手绘赛璐璐，见 `03_美术/16_赛璐璐风格规范_v0.1.md`）
- **背景**：单人 3 个月，无法产出高细节像素画/手绘动画。
- **决策**：角色/敌人用 2D 剪影 + 少量手绘细节；雨、霓虹、扫描线、故障、热浪用 Godot 2D shader；环境模块化。
- **后果**：风格统一、产出快；细节靠光影/特效；需要早点定色板与 shader 库。

## ADR-005：阿绫复用阿针骨架

- **状态**：已采纳
- **背景**：双主角动画量翻倍，单人做不完。
- **决策**：阿绫是阿针骨架 + 故障 overlay + 不同色相/特效 + 少量专属动作（闪现、过载）。
- **后果**：省一半动画；叙事上也成立（同一具身体里的两个人）；需要 shader 区分姿态。

## ADR-006：无血条，用完整度 + 花屏表现

- **状态**：已采纳
- **背景**：赛博朋克身体恐怖；想减少 HUD。
- **决策**：完整度不显示数字；角色身上花屏、断线、火花；同步率用底部一条线。
- **后果**：沉浸感强；可读性需测试；低视力玩家需要辅助选项（数字/高对比）。

## ADR-007：M 级，但不做猎奇与性内容

- **状态**：已采纳
- **背景**：断肢、机油/血、义体撕裂符合世界观；但不想做成猎奇。
- **决策**：暴力风格化、镜头克制；无性内容；阿针/阿绫的暧昧停留在情绪与共感。
- **后果**：商店页需内容警告；受众更广；叙事更依赖潜台词。

## ADR-008：先做 itch demo，Steam 后置

- **状态**：已采纳
- **背景**：3 个月切片；Steam Direct 约 $100 且需要商店素材/审核。
- **决策**：W12 先发 itch.io 免费 demo；切片数据好再考虑 Steam。
- **后果**：无前期费用；Steam 页面/愿望单后置；需要 itch 页面素材。

## ADR-009：存档用 ConfigFile/JSON + 原子写

- **状态**：已采纳
- **背景**：单人、3 槽、自动存档；不需要数据库。
- **决策**：`ConfigFile` 或 JSON；临时文件 + rename；schema 版本 + 迁移函数；损坏回退。
- **后果**：简单可靠；需要写迁移测试。

## ADR-010：剧情挂在 Boss/关卡结构上，不搞长播片

- **状态**：已采纳
- **背景**：单人做不了大量动画/配音；动作游戏节奏怕打断。
- **决策**：序章/结尾用短演出；中间靠 Boss 台词、关卡变化、脑内对话、可选记忆补丁。
- **后果**：节奏紧凑；需要写得准；玩家可能错过部分文本（可接受）。

## ADR-011：输入动作保持代码注册，不迁回 InputMap

- **状态**：已采纳（2026-10-22）
- **背景**：ADR-002 计划 M2 前把动作迁回 `project.godot` 的 InputMap。此后 `InputRebind` 已经成为键盘绑定的唯一真相（默认键 + 重绑 + `user://settings.cfg` 持久化），`InputSetup` 只管手柄；`project.godot` 里没有 `[input]` 段。
- **决策**：不迁回。动作与默认键继续由 `InputRebind` / `InputSetup` 在启动时注册。
- **后果**：键位只有一处真相，重绑不会和编辑器里的默认值打架；编辑器 Input Map 面板仍看不到动作，查默认键看 `input_rebind.gd`。

## ADR-012：战斗判定由帧表驱动，动画只跟随

- **状态**：已采纳（2026-10-22）
- **背景**：轻击三段的判定帧、顿帧、取消窗已按 60fps 帧表定稿（`scripts/combat/attack_spec.gd` + `data/combat/light_frames.tres`，生产规格 `03_美术/24_*`、`26_*`），`test_attack_spec` / `test_light1_behavior` / `test_stage_cancel` / `test_combo_consistency` 等 headless 套件按帧表断言。玩家目前是 `Polygon2D` 白盒；接入手绘动画时，需要决定 AnimationPlayer 与逻辑谁是主。
- **决策**：逻辑为主。判定时刻、取消窗、顿帧、冷却只读帧表；动画按帧表的帧号播放、对齐，不用 AnimationPlayer 的方法轨道（call method track）触发命中、取消或状态迁移。动画时长与帧表不一致时改动画，不改逻辑。
- **替代方案**：动画驱动（方法轨道发命中事件）——美术改一帧就改了手感，且 headless 下不播动画，现有测试全部失效。
- **后果**：手感数值只有一处真相，headless 门禁在接美术后仍然有效；美术出图必须严格按帧表帧数（生产规格已按帧写）；需要一个"按帧号设置动画帧"的小适配层（`PlayerVisual`），替换 `_draw` / `Polygon2D`。
