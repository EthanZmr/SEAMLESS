## 二、P0：必须改（4 条）

### P0-1 · 时间账自相矛盾：「4f 实际 50–66.7ms」与「75ms 冻结在 4f 内」不能同时成立

**证据**：
- 标题：「hit-stop 75ms 在 4f 内 → 真实感知 0.275s」。
- 时间轴：「hit-stop 75ms · 4f 内 · 不占额外帧（4f 实际 50–66.7ms）」。
- ② 第 4 条：「hit-stop = 75ms…计入 4f 内，使 4f 实际持续 50–66.7ms」。

**问题**：如果 75ms 冻结真的在 4f 内，4f 的实际持续时间必须被拉长，不可能仍是 50–66.7ms（=16.7ms）。按代码时序：

| 段 | 名义时间 | 实际时间 |
|---|---|---|
| 4f 前半（50–60ms） | 10ms | 10ms |
| 60ms 触发 hit-stop，冻结 75ms | — | 60–135ms |
| 4f 剩余（135–141.7ms） | 6.7ms | 6.7ms |
| **4f 合计** | 16.7ms | **50–141.7ms（91.7ms）** |
| 5f 起 | 66.7ms | **141.7ms** |
| 12f 结束 | 200ms | **275ms** |

**正确写法**：
- 4f：名义 50–66.7ms，含冻结实际 **50–141.7ms**（91.7ms）；
- 5f：从 **141.7ms** 开始（不是 66.7ms）；
- 总真实 275ms（这一条标题是对的）；
- 「使 4f 实际持续 50–66.7ms」改成「使 4f 实际持续 50–141.7ms」。

**影响**：现在这张图同时告诉读者「75ms 在 4f 内」和「4f 只有 16.7ms」，程序按后者做动画，冻结会无处安放；动画师按前者做，时间轴对不上。

### P0-2 · 时间轴 4f 格宽度没体现 91.7ms

**证据**：时间轴上 4f 格与 1f 格等宽（约 70 图内 px）。如果真的 91.7ms，按 1 帧 16.7ms ≈ 70px 的比例，4f 应宽约 385px（5.5 倍）。

**问题**：文字说「并入 4f 内」，视觉上 4f 仍是 16.7ms。读者扫描时间轴得到的仍是「12 个等宽的帧 + 一个看不见的冻结」。

**建议**：二选一——
- (a) 4f 格内画一条 **75ms 的红色冻结条**（占 4f 格内 60–135ms 段），格宽保持等比但内部标出冻结区间（V6 的做法更清楚）；
- (b) 4f 格加宽到按真实时长比例（4f = 91.7ms，后面 5f–12f 相应后移），时间轴总宽 = 275ms。

推荐 (a)：帧号仍按逻辑帧，冻结用色带表达，不破坏 12f 的等距视觉。

### P0-3 · 「瓶颈」没删干净，且「硬直」用词错

**证据**：右上角实际文字仍是：

> `whiff: 空挥不可跳不可连段，走完 12f（瓶颈）· 硬直 11f`

④ 第 6 条声明「右上「瓶颈」用词错 → 改为「硬直」」，但图上变成了 **「（瓶颈）· 硬直 11f」** 两个词并存——修改没删原文，只追加了新词。

**问题**：
1. 「瓶颈」不是惩罚，语义错；
2. 「硬直」也不准确——whiff 是「空挥惩罚 0.2s」（玩家不能取消），「硬直 11f」是敌人受击的 stagger（sweeper.gd:146 `stagger(0.18)`）。两个概念被并到一行，读者会以为角色空挥有 11f 硬直。

**建议**：改成两行——
- `whiff：空挥不可跳/不可连段，走完 12f（空挥惩罚 0.2s）`
- `敌人受击：stagger 11f（sweeper.gd:146）`

### P0-4 · 5f 收手过快，与「定格尾」矛盾

**证据**：4f 角色手臂前伸到 79px（针尖抵住假人近边缘 79px），5f 角色手臂已收到胸前（目测针尖退到约 30–40px）。1 帧内收 40–49px。

**问题**：
- 60fps 下 1 帧移动 49px = 2940px/s，动画上必然跳帧；
- 5f 的语义是「hit-stop 尾帧」：**假人保持后仰最大位，角色也应保持 4f 的前伸姿势**，只让白闪消散、青线从绷紧转松。收手应从 6f 开始。
- 现在 5f 收手，等于把 6-12f 的 7 帧收招压成「5f 已收完 + 6-12f 只回正」，收招节奏前重后空。

**建议**：
- 5f：角色手保持前伸（针尖 79px），白闪 alpha 降到 0.3，青线由绷直转微松，假人后仰最大；
- 6f 起：手腕内翻、针后退，6–12f 共 7 帧收 79px（约 11px/帧），节奏均匀。

## 三、P1：应改（6 条）

1. **`COMBO_ACTIVE_FRAME = 4` 是编造的常量**。代码里只有 `player.gd:31 const COMBO_ACTIVE := [0.06, 0.07, 0.09]`（秒），`grep -rn COMBO_ACTIVE_FRAME` 无结果。应写「COMBO_ACTIVE[0] = 0.06s ≈ 3.6f → 第 4 帧」。这是第三次出现「代码事实栏写不存在的东西」（前两次：48px 半宽、132 外框）。**建议立一条规矩：代码事实栏每一条必须能被 grep 命中，否则不写。**
2. **① 表格缺「推假人站位 93 / 0.727」行**。表格只有「教学档 96 / 0.750」，文字段有「站位 93」，表格与正文不一致；读者只扫表格会以为推荐站位是 96。加一行：`推假人站位 93 / 0.727`。
3. **「躯干前伸 42」仍未注明含不含前倾 12–16**（V6 评审 P2-1 遗留）。③ 第 2 条写「0.328 前伸 + 0.289 针身」，但 42 是否已含前倾没拆。建议标注「42 = 躯干前倾 12–16 + 手臂 26–30」。
4. **「输出判定」未改「判定生效」**（V6 评审 P2-3 遗留）。4f 格仍写「输出判定」。
5. **笔误 4 处**：`针腈肩转动` → `针随肩转动`；`颈肩分是错开` → `颈肩分界错开`；`回腰侧/腰侧` → `回腰侧/体侧`；`改出 Δt = 0` → `改为 Δt = 0`。底部 `13f 第三段..` 不完整。
6. **「空挥线 128 / 1.00」缺解释**。判定只有 84px，128 是「1 身高」，但为什么空挥线是 128？是「角色前进 128px 仍未命中即判空挥」还是「最远敌人距离上限」？需要一句定义，否则这行是悬空的。

## 七、结论

V7 把 V6 评审的 4 条 P0 + 6 条 P1 全部改了，**smear 从「独立格」变成「叠加帧」这一条是六版里最关键的结构修正**——它让 12f = 0.200s 第一次真正成立。

但还有 4 条 P0：
- **P0-1（时间账矛盾）和 P0-4（5f 收手）是必须改的硬伤**，改完才能交给动画师；
- **P0-2（4f 格宽）和 P0-3（瓶颈/硬直）是视觉与措辞问题**，半小时能改完。

改完这 4 条，V7 就可以作为 `light_attack_01` 的生产规格定稿，进入 12 帧逐帧贴图和 Godot 动画实现。之后的问题就是工程实现（smear 叠加层、whiff 机制、跳取消上限），不再是设计图的问题。
