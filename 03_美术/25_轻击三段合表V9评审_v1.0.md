## 2. P0（不改不能进生产）

### P0-1 二段「拽」在代码里不存在，方向还是反的

图：`160px/s 敌人被拽向角色 11px`，判定框旁红箭头指向玩家。
代码（`player.gd:594`）：

```gdscript
knockback = float(COMBO_KNOCKBACK[combo_index])   # [120, 160, 320]，二段 +160
enemy.set("velocity", Vector2(signf(offset.x) * knockback, ev.y))
```

`offset = enemy.global_position - global_position`，`signf(offset.x)` 是「从玩家指向敌人」。乘正数 = **把敌人推离玩家**。所以二段目前把敌人推开 **14.2px**（`160²/(2×900)`），不是拽近 11px。

要落地「拽」，代码必须改：二段 knockback 取负，或新增 `COMBO_PULL = [0, -160, 0]`；还要处理敌人被拉向玩家时的重叠/碰撞。

### P0-2 判定触发时刻三个口径

| 段 | 图上 | 代码实际 | 帧窗口 |
|---|---|---|---|
| 一段 | 66.7ms | **60ms** | 4f = 50–66.7ms |
| 二段 | 75ms | **70ms** | 5f = 66.7–83.3ms |
| 三段 | 100ms | **90ms** | 6f = 83.3–100ms |

`attack_active = [0.06, 0.07, 0.09]`，触发是 `elapsed >= active` 的那一刻；66.7/100 是帧边界，75 既不是触发点也不是边界，无来源。统一写「触发 60/70/90ms（落在 4/5/6 帧内）」。

### P0-3 三段位移三个数

- 四段对照表：`320px/s → 27px`
- 判定框：`敌人位移 57.6px（0.45 身高）`
- 判定框旁：`32px 侧推`

物理值：`320²/(2×900) = 56.9px`（0.445 身高）。**统一为 57px，删掉 27 与 32**；「侧推」若真要横向位移，代码不支持（只沿 offset.x 推），不能画。

### P0-4 针身系数又抄回 0.228

`37 / 128 = 0.289`。V8 评审已指出应改 0.289，V9 比例尺表又写 `0.228`（= 29.2px）。表里其余 9 个系数全对，只这一格错。

### P0-5 whiff 又写成「硬直 11f」

右上：`whiff: 空挥不可跳不可连段，硬直 11f`。
- whiff = 玩家空挥惩罚（走完 12f 收招）
- 11f = **敌人**受击硬直 `stagger(0.18)`

V8 已改成「敌人受击 stagger 11f」，V9 回归成「whiff 硬直 11f」。**这是同一个错误第二次回归**，必须拆成两行写。

## 3. P1（影响可执行性）

1. **08 §1.4 没改**：图上写「本版改写为三段递进，详见 08 §1.4 修订」，但 `08_主角形象与动作系统_v0.1.md` 仍是「一段向下短刺 / 二段反手回拉 / 三段扎进打结」。文档没落笔就写「详见修订」，是 V6–V8 反复出现的同一个问题。
2. **二段 13.2f 不是整数帧**：60fps 下只能 13f（216.7ms）或 14f（233.3ms）。图注说「不要为凑整改 COMBO_TIMES」是对的，但帧表必须二选一：建议 **13f，早 3.3ms（1.5%）**，无需改常量。
3. **二段判定框 88 > 一段 84，动作却是「拽」**：拽应该更短、且需要「钩住」的接触判定。88px 比刺还长，几何与动作语言相反。建议 76–80px，或把二段改成「甩线—钩住—回拉」的持续接触判定。
4. **三段缺 1f**：帧带从「2-5f 蓄力」起，1f 没标。一/二段都从 1f 起，三段漏了。
5. **三段「18f 收招（录入 stagger 11f）」混写**：stagger 11f 属于敌人，不是玩家 18f 收招。应拆成「18f 收招 / 敌人 stagger 11f」。
6. **「cancel 5f/8f/9f」被当成三段通用规则**：24 号文档明确二段/三段仍走旧规则（判定触发即可取消、随时可排队）。图上把第一段的规则套到三段，与代码不符；要么改代码统一，要么图上标「仅一段」。
7. **四段对照表「判定帧」行合计列写 42**：42 是伤害合计，错位到判定帧行。

## 4. P2（表述）

1. **真实感知 1.06s 应为 ≈1.04s**：hit-stop 期间动画以 0.06× 推进，不是 100% 叠加。`270.5 + 318.7 + 450.4 = 1039.6ms`。差 20ms 可忽略，但既然叫「真实感知」，写 ≈1.04s 更准。
2. **「三段后跳惩罚 0.30s」用词错**：代码是 `attack_cd = ATTACK_COOLDOWN`（攻击冷却），不是跳惩罚。
3. **「代码 30fps？」带问号出现在「代码事实栏」**：事实栏不该有疑问句，应写「工程 physics_ticks_per_second = 60」。
4. **「32px 侧推」未解释**：与 P0-3 一并删。
