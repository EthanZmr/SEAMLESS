## 1. 动作语言（定稿 v9：刺 → 拽 → 打结）

| 段 | 一句 | 关键姿势 |
|---|---|---|
| 1 刺 | 平刺，针尖停住一帧，再收线 | 6 |
| 2 拽 | 反手缠线、后坐，把线抽紧；命中后敌人被拽向自己 | 6 |
| 3 打结 | 上步扎进，双手拉线打结；最重、最远击退 | 9 |

必须继承 `08 §3.3`：预备≤6f、命中 1 帧停针、收招像收工具、受击护左肩、跑动有重量、不换骨架。

## 2. 二段「拽」帧表（13f @60fps = 0.2167s）

| 帧 | 事件 | 说明 |
|---|---|---|
| 1–4f | 起手 | 反手缠线、重心后坐；脚位可换步 8–12px，root 位移 ≤1px |
| 5f | 判定 | `COMBO_ACTIVE[1]=0.070s`；84×62 → 本段 88×62 |
| 5f | hit-stop 105ms | 冻结真实时间，不计入 12f 动画 |
| 6–12f | 回位 | 线松、针回腰侧 |
| 13f | 收招 | 无硬直；10f 起接受三段输入（排队），6–9f 可跳取消 |

**拽的数值**：

- 命中时给敌人速度 `-min(160, sqrt(1800 × max(0, d - 28)))`，`d` = 命中瞬间敌人与本机的水平距离。
- 位移 = v²/(2×900)：距离 88px 时拉 14.2px；距离 40px 时拉 12px；距离 ≤28px 不拉。
- **28px 是硬下限**：玩家半宽 14 + 敌人半宽 14。敌人 layer 4 / 玩家 layer 2，双方 mask 只有 1（世界），move_and_slide 不会互相阻挡，所以必须由数值保证不穿模。
- 击退栏的 `COMBO_KNOCKBACK[1]=160` 保留为速度上限，方向取负。

**验收**（`test_combo_grab`）：

1. 88px 命中 → 73.8px ±2
2. 40px 命中 → 27–30px（不得 <27）
3. 一段对照 80px → 88px ±2（原击退不变）

## 3. 三段「打结」帧表（18f @60fps = 0.300s）

| 帧 | 事件 | 说明 |
|---|---|---|
| 1f | 起手过渡 | 从二段收招切进蓄力（不是新起手） |
| 2–5f | 蓄力 | 前冲 90px/s；脚位可换步，root ≤1px |
| 6f | 判定 | `COMBO_ACTIVE[2]=0.090s`；100×62 |
| 6f | hit-stop 160ms + punch 0.055 | 最长停顿；相机轻微 punch |
| 7–12f | 收紧 | 线绕环、双手拉；敌人仍被压住 |
| 13–17f | 击退 | 320px/s → 56.9px 位移 |
| 18f | 收招 | 收针回腰侧；`attack_cd = 0.30` |

**验收**：

1. 判定帧落在 0.090s（第 6 帧），误差 ≤1 帧
2. 击退位移 56.9px ±4
3. 三段后 `attack_cd == 0.30`，冷却内再按攻击不进入 ATTACK

## 4. 取消与连段（D2 已拍板：统一规则、窗口按段取）

| 段 | 跳取消窗 | 连段输入 | 空挥 | 结束后 |
|---|---|---|---|---|
| 一段 | 5–8f | 9f 起 | 全禁，走完 12f | 无 CD，`combo_grace 0.40` |
| 二段 | 6–9f | 10f 起 | 全禁，走完 13f | 无 CD，`combo_grace 0.40` |
| 三段 | 13–17f（击退段） | — | 全禁，走完 18f | `attack_cd=0.30`，**取消也不退** |

- 统一的是**规则**：命中才开窗（`attack_hit_landed`），空挥一律不可跳、不可连段。
  一段曾用 `attack_hit_done`（判定帧执行过），空挥也能取消，是三段里唯一的漏洞，已随 D2 一并改掉。
- 窗口按段算：命中帧不同（4/5/6f），照抄 5–8f 会让三段的窗在命中前打开。
- 三段**可以取消，但取消不退冷却**：13f 起（打结+击退已经播完）允许跳走，买到的是机动
  ——跳起追、躲第二只、换位；`attack_cd` 仍从取消那一刻起算 0.30s，攻击空窗不被跳过。
  若取消清零冷却，取消就变成严格优于不取消，玩家没有选择，只有唯一解。
- 取消窗之外的按键会被吞掉（`InputBuffer.clear_action`），不会延迟到收招后补发。
- 空中/挑空攻击不吞键、不取消，跳跃缓冲留到落地后生效（保持旧行为）。

测试：`tests/test_stage_cancel.gd/.tscn`，7 cases / 14 assertions。

## 5. 与 V9 设计图的差异（画稿需同步）

| V9 图 | 本规格 | 原因 |
|---|---|---|
| 二段 13.2f | 13f（0.2167s），代码 0.220s | 帧号只能是整数；动画慢放 1.5% 对齐 |
| 二段「160px/s 敌人被拽向角色 11px」 | 14.2px（88px 起手），贴身递减 | 11px 是错算；按 160²/1800 得 14.2 |
| 三段「敌人位移 57.6（0.45 身高）」 | 56.9px（0.445 身高） | 320²/1800=56.9；57.6 是取整误差 |
| 三段「32px 侧推」 | 无侧推 | 代码只有水平击退，没有侧推；删或改代码 |
| 「18f 收招（录入 stagger 11f）」 | 18f 收招；stagger 11f 是敌人受击，不是本招 | 两个概念不能混写 |
| cancel 5f/8f/9f | 按段：一段 5–8f、二段 6–9f、三段 13–17f（击退段） | V9 当成三段通用规则 |
