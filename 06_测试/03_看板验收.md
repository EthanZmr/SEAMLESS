## 2. 为什么不是视频

用户 m01905 原话：“中间那块大屏真的就是视频播放啊？我要的是使用remotion动效做这个看板，不是remotion player做视频”。

v1.2 的改动：

1. 删除 `@remotion/player` 的 `<Player>` 组件；页面中不再有播放按钮、时间码、进度条、静音键、全屏视频控件。
2. 新增 `src/live/LiveClock.jsx`：`requestAnimationFrame` 驱动帧号，30fps 节奏；四章组件直接读帧号。
3. 动效仍由 Remotion 的 `interpolate` / `spring` / `Easing` 计算；不是预渲染视频，也不是 CSS 关键帧硬编码。
4. 中央画布是 1600×900 的 DOM，按容器宽度 `transform: scale()`；双击/「全屏看板」放大的是同一个 DOM 节点。
5. 切章、重播只重置帧号；没有视频源切换。
6. 手机 ≤900px 隐藏动效画布，保留下方完整数据，避免把 1600×900 压成不可读的缩略图。

## 5. 未覆盖 / 已知限制

1. **file:// 冒烟只验证外壳与资产**：Chrome headless 的虚拟时间下 `requestAnimationFrame` 不推进，截图停在首帧（只有背景、页眉与里程碑骨架）；真实桌面双击尚未人工复核。HTTP 预览下动效正常。
2. **全屏已在无头 Chromium 验证**：点击按钮后 `fullscreenElement` 为 `.live-board`，画布 1920×1080 完整；未在真实桌面按 F11/Esc 复核。
3. **移动端不展示动效画布**：≤900px 直接隐藏 1600×900 画布，显示完整数据卡；这是有意取舍，避免缩略图不可读。
4. **未测 Safari / Firefox / 低端设备**：当前只测 Chromium；CSS 使用 `backdrop-filter`、`mask-image`，旧浏览器会降级但不影响内容。
5. **无音频**：四章只有视觉动效。
6. **数据与动画不同步的风险**：章节内部分数字来自 `project.json`；改数据后必须重新构建，页面不会自动刷新。
